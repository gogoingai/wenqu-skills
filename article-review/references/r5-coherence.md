# R5：连贯性、清晰度与理解路径（第一步跑）

**每次审查的第一步**：先整体读一遍，再逐节、逐段检查。R5 关注读者能否建立正确理解；它不判断题材是否合适，也不把某种学术或技术表达本身视为问题。

## 一、先读取读者基准

优先读取文章存储中的读者画像与写作目标。技术专家文章可以保留必要术语和推导；面向更广读者的文章则需要补足背景。

如果没有读者基准，以“具备文章所要求的前置知识、但没有作者脑中隐含上下文的读者”为准。不要一律要求代码快照、场景案例或通俗化改写。

## 二、连贯性：读者能否知道为什么要往下读

### 章节之间

- 相邻章节是否有逻辑关联？结束一节时读者是否知道下一节为什么出现？
- 是否突然切换话题，或在后文才补解释前文依赖的概念？

### 段落之间

- 段与段之间是否无铺垫地切换概念、对象或时间范围？
- 引入新概念前，前一段是否给出足够前提？

### 前后一致性

- 同一机制、数字或范围条件是否自相矛盾？
- “有 N 种情况”是否确实讲了 N 种？

## 三、清晰度：读者能否在脑中建立正确模型

读者看不懂不一定是因为术语难，也可能是对象、关系或因果没有交代完整。逐段定位读者会在哪里失去理解。

| 失去理解的原因 | 检查问题 | 常见处理方式 |
|----------------|----------|--------------|
| 对象不明 | 谁在做什么，作用于谁？ | 补出主语、动作与对象 |
| 指代不明 | “它”“这一过程”“上述内容”指向什么？ | 用具体概念替代模糊指代 |
| 关系不明 | 两个概念是并列、输入输出、因果还是约束？ | 补一句关系说明，或改为表格 / 图示 |
| 条件缺失 | 在什么范围、前提或例外下成立？ | 将条件放到结论附近 |
| 信息过载 | 一句是否同时塞入多个因果、转折和限定？ | 拆句，先结论后条件 |
| 铺垫不足 | 新概念是否在读者需要它之前解释？ | 前移定义、加过渡或调整顺序 |

## 四、选择适合的理解支撑

新机制、流程、抽象评分或复杂结构不应只留在抽象描述中，但不强制使用某一种表现形式。按内容选择最合适的支撑：

| 内容 | 可选支撑方式 |
|------|--------------|
| 流程或多路径机制 | 输入输出说明、流程图、对照步骤 |
| 数据结构或多组件关系 | 字段表、数据形态、层级图 |
| 评分、阈值、权重 | 解释它反映什么、影响什么；必要时给简单算例 |
| 容易误解的规则 | 反例、对照、边界说明或简化场景 |

判断标准不是“有没有例子”，而是：读者是否已经拥有理解这段所需的最小模型。

## 五、措辞直白检查

逐句读，留意以下让读者费解或失真的措辞：

| 信号 | 处理方式 |
|------|----------|
| 抽象量词/形容词堆砌描述具体机制（如“预算”“边界”“有限”“始终使用的”） | 换成具体词或动词（Token 上限、单次提取大小、基础分数等） |
| 读者可能不懂的数学/工程术语（如“内积”“中点”“映射后”） | 结合读者基准解释、替换或在首次出现处定义 |
| 拟人/拟物化系统动作造成含义模糊（如“任务丢失”“尽力完成”“悄无声息地变成”） | 改成可观察的处理状态或结果 |
| 语法拧巴（主谓宾搭配不当、从句嵌套） | 拆成直白短句 |
| 前后半句同义重复 | 合并成一句，保留新增信息 |
| 标签/列名和内容不符 | 改标签匹配内容 |
| 表格/总结自行概括，和正文表述不一致 | 优先使用正文已确认的总结句 |

## 与其他审查项的边界

| 问题 | 归属 |
|------|------|
| 读者无法跟上对象、关系、因果或概念铺垫 | R5 |
| 直译式表达、英文语序或搭配 | R2 |
| 形式化重复、空泛收束、模板节奏 | R3 |
| 章节重复、信息形式没有任务 | R4 |
| 题材与表达尺度不匹配 | R6 |
| 本轮改动在别处没有同步 | R7 |

## 报告格式

- **连贯性：** 位置 + 缺少的承接 + 为什么读者会跳出 + 候选修法。
- **理解路径：** 位置 + 读者会在哪个对象、关系、条件或因果处失去理解 + 应补什么。
- **措辞直白：** 位置 + 当前写法为什么难懂或失真 + 候选改法。

未发现问题时，确认：`R5 连贯性、清晰度与理解路径 clean。`
