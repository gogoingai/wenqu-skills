# R4：结构、分工与信息形式

**默认跳过**。用户说“顺便看看结构”或“完整审查”时执行。

R4 看整篇文章如何组织，不逐句润色，也不检查本轮改动是否漏改。它不设置“每几节必须有引用块”“同类内容不能连续几次”之类的形式配额。

## 一、章节职责与顺序

- 每章是否回答一个独立问题，而不是与相邻章节换标题重复？
- 标题是否准确覆盖下方内容？
- 章节顺序是否符合读者建立概念的顺序：先有必要背景，再引入机制与细节？
- 重要概念是否在首次被频繁使用前得到解释？
- 一节是否塞入两个可独立理解的主题，应拆分或重新归属？
- 章节结尾是否自然把读者带到下一节，而不是突然跳转？

## 二、覆盖范围与重复

- 每个重要机制是否按文章题材覆盖必要层次：是什么、为什么、怎样实现、边界或验证？
- 同一机制是否被多处重复展开；当前章节删去重复内容后，会不会影响当前位置的理解？不会 → 应删或带过。
- 是否因追求“完整”而引入与主线无关的边角细节？
- 总结段是在收束、承接还是仅换词复述正文？

## 三、信息形式是否有明确任务

| 形式 | 适合承担的任务 | 不应因为这些理由强加 |
|------|----------------|----------------------|
| 表格 | 多项映射、比较、字段或阶段差异 | 仅为让页面看起来更丰富 |
| 列表 | 并列原因、条件、步骤或边界 | 把一段本应连贯的因果拆碎 |
| 引用块 | 值得单独记住的结论、原则或限制 | 凑视觉停顿或固定出现频率 |
| 图示 | 关系、层级、流程、状态变化等线性文字难以清楚表达的内容 | 复述一张普通列表即可说明的信息 |
| 加粗 | 关键结论、设计取舍、图表后的引导句 | 整段加粗或仅为排版制造重点 |

## 四、格式与图示基础检查

- 前言自然流动，不把 SCQA 等内部框架标签写成正文标题。
- 公式、权重等概念性内容使用 LaTeX、图示或自然语言解释，不用代码块伪装工作原理。
- 正文没有裸露的 Mermaid、draw.io、Graphviz、PlantUML 等画图 DSL；配图质量由 wenqu-image 负责。
- 文件路径、命令、字段名用行内代码；中文概念、章节名不滥用行内代码。
- 加粗、表格、列表、引用块与图示各自有信息任务，整体读起来不被某一种形式长期主导。

## 报告格式

- **章节职责重叠：** 涉及章节 + 重复的内容 + 建议保留在哪一处。
- **顺序或铺垫不足：** 位置 + 读者缺少的前提 + 调整顺序或补过渡的建议。
- **结构粒度不当：** 小节 + 混入的主题 + 建议拆分、合并或重命名。
- **信息形式不匹配：** 当前形式 + 没有承担的任务 + 适合的替代形式。

未发现问题时，确认：`R4 结构、分工与信息形式 clean。`
