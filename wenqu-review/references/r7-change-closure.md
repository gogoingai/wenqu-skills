# R7：变更闭环与全篇一致性

R7 专门检查“这里改了，别处是否还留着旧说法、旧结构或旧图示”。它不替代 R0 的事实核验，也不重新做 R5 的逐句润色。

## 何时运行

在以下情况运行：

- 修改术语、机制、数字、限制、范围、标题、章节顺序或图片；
- 用户说“整体检查”“提交前检查”“这轮都改完了吗”；
- 执行完整审查。

纯标点或单句微调不强制运行。

## 一、确定本轮改动

按以下优先级确定检查范围：

1. 用户确认的改动清单；
2. `wenqu-skills/{文章名}/references/change-impact.md` 中本轮未闭环的记录；
3. `wenqu-skills/{文章名}/references/terms.md` 中本轮调整过的推荐词与适用范围；
4. 当前 `git diff`；
5. 用户在本次会话明确说明的改动。

若只能使用第 4 或第 5 项，先说明“本轮没有完整变更影响记录，R7 只能按可见改动检查”。不得把不确定的范围报告为“全文已无遗留”。

## 二、五类闭环检查

| 类别 | 检查范围 |
|------|----------|
| 术语遗留 | 旧名称、近义混用、旧缩写、概念范围漂移 |
| 逻辑遗留 | 旧结论、旧转折、旧数量词、相互冲突的条件与边界 |
| 结构遗留 | 标题、目录、交叉引用、章节过渡、总结段 |
| 内容载体遗留 | 表格、列表、公式说明、案例、反例、参考说明 |
| 图文遗留 | 图中文字、图注、待配图描述、画图提示、图片链接所表达的旧结构 |

## 三、执行步骤

1. 写下“旧说法 / 新说法 / 影响对象 / 不变边界”。
2. 用全文搜索定位旧说法、近义表述、章节引用与标题。
3. 逐一检查改动关联的前后过渡、表格、列表、总结、案例和公式说明。
4. 若该章节有图片，检查图中文字、图注、画图提示与当前正文是否仍对应；图片是否需要重新生成，由 wenqu-image 流程向用户确认。
5. 检查 `references/status.md`：本轮已确认的章节、图片、审查与发布状态是否同步；正文或图片已变更却仍标记“已采用 / 完整通过”时，改为待复查。
6. 按文章状态中的反向验收确认本轮是否完成：未达到条件时保留下一步，不得报告为“全文已同步”。
7. 报告遗留项，或明确本轮检查覆盖范围后确认闭环。

## 常见遗漏

- 将一个术语替换后，图注、表格列名或章节总结仍使用旧词；
- 删除一个分支后，仍保留“两个问题”“三种路径”等数量词；
- 调整章节顺序后，“见第 X 节”“接下来讨论”指向错误；
- 修改机制边界后，前言、案例、结论仍在表达旧范围；
- 正文改完了，已生成图片或画图提示仍包含旧节点、旧箭头或旧限制；
- 改动限制条件后，反例、公式解释或评测口径没有同步。
- 图文已更新，但状态文件仍显示旧版本、已采用或无需复查；
- 改动清单已执行，却没有达到本轮声明的章节／图片／全文完成条件。

## 报告格式

- **检查基准：** 本轮改动源 + 可覆盖范围。
- **遗留项：** 改动源头 → 遗留位置 → 遗留内容 → 为什么需要同步 → 建议处理。
- **闭环确认：** 明确写出已检查的类别；不要只写“全文一致”。

未发现遗留时，确认：`R7 变更闭环完成：已检查[术语 / 逻辑 / 结构 / 内容载体 / 图文]。`
