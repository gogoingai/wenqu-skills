# crwl 浏览器检索恢复

本文件定义 `open-websearch` 直连检索的**受限恢复**。它不是第二个默认搜索通道：每组关键词仍必须先跑 agent 原生搜索，再跑可用的 `open-websearch search`。只有直连引擎本次失败或没有候选，才可按本文件执行一次 `crwl` 浏览器检索。

## 统一调度，不统一食谱

十个 `open-websearch` 引擎都进入同一调度流程，但不能把同一段 DOM 选择器套给所有网站。根据引擎的实际检索面选择处理方式：

| 引擎 | 直连后的处理 | 浏览器恢复与候选 URL 规则 |
| --- | --- | --- |
| `baidu` | 直连失败或空结果时可恢复 | 用百度结果页提取结果卡；只保留可确认的原站 URL |
| `bing` | 直连失败或空结果时可恢复 | 用必应结果页提取结果卡；从跳转 URL 的 `u=a1...` 参数解码目标 HTTPS URL，无法解码则丢弃 |
| `brave` | 直连失败或空结果时可恢复 | 用 Brave 结果页提取原站链接，不把页面导航、图片或视频聚合项当普通网页候选 |
| `sogou` | 直连失败或空结果时可恢复 | 用搜狗结果页结构化提取；优先从 `pcurl`，其次从 `url` 参数还原并百分号解码原站 URL，绝不入库搜狗包装跳转链接 |
| `linuxdo` | 不另开浏览器恢复 | 它是对 Bing、DuckDuckGo 或 Brave 的 `site:linux.do` 委托与筛选；跟随被委托引擎的结果，不能当独立索引 |
| `csdn`、`juejin` | 保持站内接口优先 | 不为直连失败默认再抓通用 SERP；需要正文时用普通下载食谱 |
| `duckduckgo`、`startpage` | 保持直连 HTML 优先 | 尚未定义通用浏览器恢复食谱；失败时保留其它渠道并降级，不猜测 DOM |
| `exa` | 保持直连服务优先 | 不用浏览器模拟长期替代正式检索接口；如需稳定配额或筛选能力，先取得用户对官方 API 凭据的授权 |

上述“可恢复”是运行条件，不是成功承诺。页面出现验证码、登录、付费墙、空结果、页面结构不符或目标 URL 无法还原时，记录失败并继续其它候选；不得通过反复请求、导入用户登录态或规避访问控制来处理。

## 执行规则

1. 从 `open-websearch` 的 `partialFailures`、无候选结果或整体失败中识别**本轮**可恢复引擎；不要根据历史某次失败盲目开启浏览器。
2. 同一引擎、同一关键词组最多执行一次浏览器检索；串行运行，避免并发浏览器和无意义重试。
3. 通过 `crwl -e <extractor> -s <schema> -o json` 提取结果卡的标题、摘要和链接；选择器必须对应当前引擎页面，不能复用别站 schema。
4. 先还原并校验原始 URL，再写入候选池。候选渠道记为 `crwl-serp:{engine}`；若同一 URL 已由原生或 `open-websearch` 找到，在同一条素材上合并渠道。
5. 将浏览器结果与所有已有候选统一去重、分级后才下载。浏览器 SERP 只负责发现，正文仍优先走 `crwl` 下载食谱或 agent 原生下载。

## 公众号：专用同会话发现

公众号发现不走通用搜狗结果恢复。搜狗微信结果链接通常依赖当前页面会话，先提取链接、再由另一条 `crwl` 命令访问会丢失上下文。因此使用 `site-recipes.md` 的“搜狗微信发现”路径：一条调用中打开结果页、选择结果、等待 `#js_content`，再从最终正文确认原始 `mp.weixin.qq.com` URL。

该路径只能用于已确认题名的候选：将题名、账号名和主题写入查询词，再在当前页面按题名精确定位。没有唯一匹配项时不点击、不猜测排名；若仍不能确认文章身份，不把它作为事实素材入库。
