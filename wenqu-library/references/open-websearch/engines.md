# open-websearch 引擎选择

下表是 CLI 接受的引擎名称，以及它们适合补充的素材范围；名称必须使用代码形式传给 CLI。

| 引擎 | 适合 Wenqu 的候选发现 |
| --- | --- |
| `baidu` | 泛中文网页与中文资料发现 |
| `bing` | 广泛网页补充；需要时可单独启用 Bing 的 `--search-mode` |
| `linuxdo` | LinuxDo 社区讨论与经验帖 |
| `csdn` | CSDN 开发者文章与教程 |
| `duckduckgo` | 广泛英文网页补充 |
| `exa` | 广泛网页补充与交叉检索 |
| `brave` | 广泛网页补充与交叉检索 |
| `juejin` | 掘金技术文章 |
| `startpage` | 通用英文网页发现 |
| `sogou` | 搜狗中文搜索；公众号发现交给专用的搜狗微信同会话食谱 |

别名中只有 sogou/sougou/搜狗 可靠；其他引擎一律使用上表代码名。

## 运行时处理

引擎名称表示“可以请求的候选来源”，不是对每次检索结果的承诺。每次只合并实际返回的候选；单个引擎无结果或失败时记录执行信息，继续使用 agent 原生搜索和其他成功来源，不把某个引擎设为收集前提。

直连失败后，不要把十个引擎一律改用浏览器。只有 `baidu`、`bing`、`brave`、`sogou` 具备浏览器恢复食谱；其他引擎按其自身检索方式保留直连或直接降级。完整分流与 URL 还原规则见 `../crawl4ai/search-recovery.md`。

## 选择规则

| 素材目标 | 优先补充引擎 | 说明 |
| --- | --- | --- |
| 中文技术文章 | `baidu,juejin,csdn` | 覆盖泛中文网页与开发者社区；总 limit 按三者分摊 |
| 微信公众号 | `sogou` | 直连结果只作普通补充；不足时用 Crawl4AI 的搜狗微信同会话发现食谱，不重放跳转链接 |
| LinuxDo 经验与讨论 | `linuxdo` | 仅作外部观点/案例，不能替代实现事实 |
| 英文文档或国际文章 | `startpage` | 不足时再加 `bing` 或 `duckduckgo` |
| 多源交叉核验 | 两个不同类型引擎 | 仅在原生搜索和首轮补充不足或冲突时使用，不为凑数量盲目全选 |

不要默认十引擎全开：会稀释每个引擎的 limit、增加不必要请求，也不会替代 agent 原生搜索。引擎选择是候选发现策略，不是可信度评级；最终仍按来源优先级和原文内容分级。

## 论文与研究报告：原生搜索主导

这十个引擎中**没有学术专用引擎**，所以“搜索论文”不能套用普通技术文章的三引擎组合：

1. agent 原生搜索必须先按论文题名、作者、DOI、会议或期刊名和年份检索，并优先定位 `arXiv`、DOI 落地页、会议或期刊官方页、机构仓储或作者公开页。
2. `open-websearch` 只补充外围材料：可用 `startpage`、`bing` 或 `duckduckgo` 查相关文章、工程解读与公开镜像；只把实际返回的结果加入候选，不能把它当作论文索引或引用数据库。
3. 素材索引中将论文正文、官方摘要、二手解读分别标为不同来源类型；事实主张优先回到论文 PDF 或官方落地页，二手文章只能作写法参考或背景。
4. 下载时优先保留论文 PDF 或官方摘要页；`crwl` 对页面正文无效时改用 agent 原生下载，并记录“PDF/页面下载方式”，不把搜索摘要当作论文原文。
