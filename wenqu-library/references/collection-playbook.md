# 素材收集执行手册

四步流程（规划 → 搜索 → 下载 → 整理）每一步的具体执行方法。SKILL.md 是概览，本文件是操作细则。

## 第 1 步：规划

**输入**：题目方向、写作目标、目标读者、范围锁定、已明确的关键词/模块名（来自 wenqu-write Step 1/1.5，或用户直接给出）。

**产出：收集清单**（全流程唯一确认点），格式：

```markdown
## 收集清单

### 相似文章（写法参考，找 2~4 篇）
| 想找什么 | 搜索关键词 |
| 讲 XX 系统的技术长文，结构偏源码拆解 | "XX 源码解析"、"XX deep dive"、"XX 原理" |
| 面向中级工程师的 XX 入门到实践 | "XX 入门 实践"、"getting started XX production" |

### 相关素材（事实素材，按需）
| 想找什么 | 搜索关键词 | 预期来源 |
| XX 的官方设计文档 | "XX design doc"、"XX architecture" | 官网/GitHub |
| XX 的容量/性能数字 | "XX benchmark"、"XX 性能测试" | 官方博客/论文 |
| 公众号上的 XX 实践分享 | "XX 实践 公众号" | mp.weixin.qq.com |
```

执行要点：

1. **相似文章先于相关素材**——先看别人怎么切题，再决定还缺什么料
2. 关键词中英文各准备 2~3 组，覆盖同义表达（"内存数据库"也要试 "in-memory database"、"缓存层"）
3. 清单给用户确认时顺带说明**预计抓取数量**（"相似文章 3 篇 + 文档站 1 个（限 20 页）"），让用户对耗时和体量有预期
4. 范围锁定里明确排除的内容，清单里不安排对应搜索

## 第 2 步：搜索

用 agent 自带的联网搜索工具，按清单的关键词组合逐组搜。

执行要点：

1. **每组关键词取前 3~5 条候选**，记录：标题 + URL + 一句话相关性判断（"官方文档-安装篇，相关"）
2. **来源优先级**：官方文档/源码 > 官方博客 > 知名技术媒体 > 个人博客 > 内容农场。同内容多个转载只留原始出处
3. **不确认直接下载**——搜索是低成本动作，抓回来读摘要再淘汰，比让用户逐条看 URL 高效
4. 用户直接给了 URL 的，整个第 2 步跳过
5. 搜不到满意结果时：换一组关键词再试（最多 2 轮），仍没有就在清单上标注"未找到，待用户补充"，不硬凑低质量来源

## 第 3 步：下载

**环境检查与主动安装（每次收集流程开始时做一次）**：

```bash
command -v crwl || ls ~/.local/bin/crwl 2>/dev/null
```

- **已安装** → 直接用；首次抓取报浏览器错误 → 按 README 指引跑 `crawl4ai-setup` 或 `python -m playwright install chromium` 修复后继续
- **未安装** → **主动提议帮用户装**，不要直接降级：

  > 素材抓取建议用 crawl4ai（对动态渲染页面和微信公众号效果好很多）。要我现在装一下吗？一条命令：
  > `uv tool install crawl4ai`（约 1 分钟），装完还需要下载浏览器引擎（约 300MB）。

  - 用户同意 → 执行安装 + `crawl4ai-setup`，然后 `crawl4ai-doctor` 验证，继续下载
  - 用户拒绝 / 安装失败 → 才降级为 agent 自带抓取，告知「本轮用内置抓取代替」，照样落盘登记

**抓取命令**（完整参数、实测产物结构和失败处理 → 查 `references/crwl-cookbook.md`）：

```bash
# 单页
crwl <url> -o markdown -O {materials}/articles/<域名>/<slug>.md

# 整站/文档站（产物是合并单文件，====== 分隔）
crwl <url> --deep-crawl bfs --max-pages <N> -o markdown -O {materials}/docs/<站点>.md

# 微信公众号（必须 UA 伪装，UA 里不能有逗号）
crwl <url> -b "user_agent=...MicroMessenger..." -c "wait_for=css:#js_content,delay_before_return_html=2.0" -o markdown -O {materials}/articles/mp.weixin.qq.com/<slug>.md
```

执行要点：

1. **边抓边登记**：抓完一个就先把 URL + 文件路径记进 index.md（摘要可后补），全部抓完再统一补摘要——中途出错也不丢已抓成果
2. 文件命名：`articles/` 下按来源域名建二级目录，文件名用内容 slug（从 URL 或标题提取），不用随机串
3. 批量下载时逐个串行抓，不并行（Playwright 浏览器实例吃内存，也容易触发反爬）
4. 失败的 URL 当场登记「抓取失败：原因」，全部抓完后把失败清单汇总给用户，说明哪些来源需要手动提供或替换

## 第 4 步：整理

1. **读产物写摘要**：逐个读下载的 markdown，摘要写"这篇/这份资料讲了什么、哪些内容对本篇写作有用"，一两句话，不抄标题
2. **登记 index.md**：按 SKILL.md「存储位置」的登记规则填全各列（来源类型、用途、标签别忘了）
3. **去重**：和全局文库已有 L 条目重复的，本篇引用 L 编号，不新建 M 条目；下载产物重复的删除文件
4. **回收全局文库**：判断标准——"这条素材换个文章主题还用得上吗？"用得上才提炼成 L 条目写入对应 `{主题}.md`（保留原始链接），本篇专用的不回收。全局文库只存提炼条目和链接，原始文件留本篇
5. **收尾汇报**：告诉用户本轮抓了几个来源、成功几个失败几个、登记了哪些条目、回收了什么进文库——一句话带过，不逐条复述
