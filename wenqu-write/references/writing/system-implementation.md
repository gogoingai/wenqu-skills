# 系统实现介绍

仅用于自研系统、架构设计或工程实践文章。目标是帮助读者理解设计判断，不是复述代码执行顺序。

## 组织方式

按“总—分—总”组织：先交代整体问题、能力边界和模块关系；再展开关键能力；最后说明各能力如何协作，以及这套设计带来的结果。

单个能力优先回答：

1. 为什么需要它，解决什么实际问题；
2. 为什么采用当前设计，而不采用更直接的做法；
3. 核心机制怎样工作；
4. 它向谁提供什么结果，又不负责什么。

输入、输出、规则与实现细节只在它们能帮助读者建立系统模型时展开，不机械套统一模板。

## 表达选择

- 多模块关系、前后依赖或在线离线协作：先给整体图或简表，再进入细节。
- 设计取舍、边界与多项原因：用短段配无序列表。
- 稳定映射、字段、结果类型或方案比较：用表格。
- 单一结论或一两步机制：直接写清楚，不为形式增加图表。

不要把文章写成“调用接口 A → 执行逻辑 B → 写入 C → 返回 D”的代码流水账；应说明每一步存在的原因、避免的风险和它与其他模块的关系。避免连续散文没有结构支撑，也避免整节只由表格构成。
