# 骨架写作指南

骨架是动笔前的最后确认。写错了方向比写慢更难收，所以骨架不确认不动笔。

## 骨架的颗粒度

骨架必须规划到所有层级，包括子章节（2.1、2.2、3.1……）乃至更深的嵌套层级（3.1.1、3.1.2……）。只列一级章节标题是不够的——每一个子节都要出现在骨架里，缺的层级意味着没想清楚。

每个章节（不论层级）都必须写清楚以下内容：

1. **切入角度**：从哪个问题或场景引入
2. **核心内容**：这节要让读者理解什么、记住什么；有哪些关键数字或机制要覆盖
3. **表现形式**：用图、表格、代码块还是散文；有没有具体示例
4. **引用**：这节依赖 `references/materials.md` 里的哪几条素材 ID（`M1, M5, M9`）；纯结构性的节（如"前言"里单纯交代文章结构）可以留空，但涉及具体机制/数字/例子的节必须能对应到素材库条目，对应不上的先标"待核实"而不是当既定事实写
5. **章节职责**：回答什么、不重复什么、交给下一节什么；纯目录、参考文献等非叙事章节可以省略
6. **完成标准**：读者读完本节能复述什么判断，下一节为何需要继续讲；用于正文收尾时判断本节是否真正完成

用户看骨架时应该能判断：**这节写的东西是不是我想要的？内容会不会太深/太浅？**。骨架的颗粒度要细到"如果按这个骨架写，文章基本定型了"——不是只有标题，而是每节的内容说明。

## 告诉用户

明确告诉用户：这是动笔前的最后确认，如果章节结构、侧重点、或某个机制的取舍有问题，现在改比写完再改省力得多。

## 固定约束

**第一章标题必须是「背景」或「前言」**，不得用其他名称（如"介绍"、"概述"、"引言"等）。

## 骨架前必须对齐（硬性规则，不可跳过）

**提骨架之前，必须从 `SKILL.md` 确认以下五项已有明确答案**。任何一项缺失，先补问，不得直接出骨架：

| 对齐项 | 检查内容 |
|--------|---------|
| 范围锁定 | 明确不覆盖哪些模块/细节？篇幅砍半时保留哪些核心内容？——骨架里不能出现已被排除的模块 |
| 各章节深度 | 每个主要章节是简写、设计层还是实现层？不能笼统说"视内容而定" |
| 例子策略 | 单一主线还是章节独立？主线例子是什么场景？ |
| 复杂内容处理 | 多图、多例、直觉优先还是完整推导？ |
| 重复内容处理 | 跨章节出现的相似机制，第一次详写后带过，还是每次都写差异？ |

这五项对齐好，骨架提一次就能确认，不需要反复修改。

## 骨架确认后：质量自检（不可跳过）

用户确认骨架后，动笔前先自己核对一遍（详见 `SKILL.md` Step 3.4）：三要素是否齐全无"待定"、关键机制是否都有源码 `path:line` 依据、有没有超出范围锁定、篇幅预算是否合理。自检发现的问题先给用户看，不要自己默默改完就往下走。

## 骨架示例格式

```
# 一、前言
切入：从问题痛点切入（什么场景下会遇到这个问题）
核心内容：交代系统定位、核心矛盾、解法方向
形式：散文 SCQA 结构；如有亮眼基准数字可加数据表
引用：（无，纯结构性开篇）
回答：读者为什么需要理解这个主题
不重复：不提前展开后文机制细节
交接：提出核心问题，引出整体架构
完成标准：读者能说清文章要解决的核心问题，并理解为何需要先看整体架构

# 二、整体架构
切入：先给全局视图，再拆解各层职责
核心内容：系统由哪几层/模块组成，各自做什么
形式：架构图（配图占位）+ 简表
引用：M2, M3
回答：整体由哪些部分协作，信息如何流动
不重复：不在此展开每个模块内部规则
交接：为后续逐项机制说明提供全局地图

## 2.1 核心模块 A
切入：从它解决的问题说起
核心内容：它做什么、为什么这样设计、关键数字 X
形式：散文 + 引用块高亮结论
引用：M1, M5
回答：模块 A 为什么存在、怎样工作
不重复：不抢先解释模块 B 的内部细节
交接：说明 A 的输出为何需要 B 继续处理

## 2.2 核心模块 B
切入：和 A 的关系（接收 A 的输出）
核心内容：触发条件、工作机制、数字 Y
形式：流程图（配图占位）+ 表格对比两种情况
引用：M6, M7
回答：模块 B 如何承接 A 的输出
不重复：不重复 A 已讲清的输入来源
交接：为后续结果或维护环节建立前提
```

保存到 `{项目根目录}/wenqu-skills/{文件名}/references/skeleton.md`。

## 变更历史（持久化，每次改动追加一行，不是临时对比完就丢）

骨架文件末尾固定维护这张表，首次定稿也要记一行：

```markdown
## 变更历史
| 时间 | 版本 | 改动摘要 | 原因 |
|------|------|---------|------|
| 2026-07-08 | v1 | 初版骨架 | — |
| 2026-07-09 | v2 | 合并 2.1 短期记忆 / 2.2 长期记忆 为一节「记忆层级」，检索独立成 2.2 | 短期/长期概念强相关，拆开读者要来回跳；检索逻辑够独立，值得单独一节 |
```

大改（新增大章节、调整顺序、拆分/合并子节）在追加历史行之前，先用下面的对比格式给用户看，用户确认后再执行、再写入历史表：

```
变更前：2.1 短期记忆 → 2.2 长期记忆 → 2.3 检索
变更后：2.1 记忆层级（含短期/长期对比表）→ 2.2 检索机制（独立成节）
原因：短期/长期概念相互依赖，放在一节里对比更清晰；检索逻辑足够独立，值得单独一节
```
